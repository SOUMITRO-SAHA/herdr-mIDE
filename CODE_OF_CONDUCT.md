# Code of Conduct

herdr-mIDE is a small open-source project built in public. Keep it a place
where people can collaborate, ask beginner questions, and disagree about
code without it becoming personal.

## Scope

This code applies inside this project's spaces: the issue tracker, pull
requests, code review, and any chat or forum spaces the maintainers run for
the project. It also applies when you represent the project in public.

## Expected behavior

- Be kind and assume good faith. Participants here range from first-time
  open-source contributors to long-time maintainers.
- Disagree with ideas, not people. Critique code, commits, and proposals —
  and explain why.
- Follow the contribution flow: issues before pull requests, `/claim`
  before work, and never race someone else's claimed issue — ask about
  owner, status, and ETA in a comment instead (see CONTRIBUTING.md).
- Keep the repository safe to share: never paste secrets, tokens, private
  repository content, or unreviewed screenshots into issues or pull
  requests.
- Accept that maintainers balance scope, roadmap, and time; a closed or
  declined proposal is a project decision, not a judgment of you.

## Unacceptable behavior

- Harassment, insults, trolling, deliberate derailing, or bad-faith
  arguments.
- Discriminatory or demeaning language or imagery of any kind.
- Publishing other people's private information without their consent.
- Claiming or working on an issue someone else has claimed after being
  asked to wait.
- Any sexualized attention or unwelcome advances.

## Reporting and enforcement

Report a violation to the maintainer (@SOUMITRO-SAHA) through GitHub, or
use GitHub's report-content flow on the offending comment. Reports that
also involve exposed private information follow the private path described
in [SECURITY.md](./SECURITY.md).

Maintainers review reports promptly and keep them confidential as far as
practically possible. Outcomes match severity: a private warning, removal
of comments, blocking a member from the repository, or escalation to
GitHub. Repeated violations after a warning lead to a block.

Substantive changes to this document land as pull requests so they stay
visible and discussable.
